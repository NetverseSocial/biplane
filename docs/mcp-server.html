Biplane · BIP-24 · decision brief

The ready-made connector, and which server it trusts

Plane publishes an official connector that lets AI agents drive a Plane board — create work items, move them, comment. The question is whether we install it. The short answer is not yet, and the reason is where it points by default.

Where it points

Answering your question directly: it trusts Plane’s server, not ours, unless someone remembers to point it at Pi5. Reviewers asked that it fail closed — refuse to run rather than quietly fall back to the public one.

What the reviewers found

  • Points at the wrong server by default — as above. Should refuse to start instead.
  • Writes what passes through it into its log — including credentials and ticket content.
  • Fetches attachments from any address it’s handed, with no size limit — a way to make our own server reach inside our network, or fill a disk.
  • Exposes delete unconditionally — destructive actions are not gated.
  • Outdated parts, and the build isn’t repeatable — two runs can produce different software.
  • The version reviewed does not exist. The installer pulls a different one, so the review does not describe what we would run.

Recommendation

Do not install it now — but this is not a permanent no. Most of the objection is that an outside connector could reach past our own rules. Once our permission checks sit underneath every write, an untrusted connector becomes tolerable, and the honest move is to re-review it then. The one thing that must change regardless: review a pinned, exact build and run that same one.

Sources: the BIP-24 ticket and the two recorded reviews (Rowan, Morrow); the third review, by Vex, is outstanding. Verified against the board, not from summaries.
