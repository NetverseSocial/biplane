How a ticket gets linked to code

Three claims were on the table tonight — that we rebuilt something Plane already shipped, that we grew a second filing system beside the first, and that the result is spaghetti. I opened the code. Two are false. The third is real but is not what it looked like.

The work is sound. The linking code uses Plane's own ticket tables and writes the link onto the ticket's own timeline. It did not duplicate anything, because there was nothing working to duplicate — Plane's free version ships the filing cabinet for GitHub linking and keeps the machine in their paid product.

The cost is real, and it's gold-plating. Linking a ticket to a pull request is an afternoon. Making it survive duplicate deliveries, hostile payloads, retries and three different code hosts is weeks. Those were never separated into two decisions, so the hour-long version was approved and the multi-week version was built.

The three claims, tested

ClaimVerdictWhat the code shows
We rebuilt linking that Plane already had False Stock GitHub linking is four database tables and zero logic. No handler, no sync, no background job. Nothing to extend.
We built a second filing system beside the first False The linking code imports Plane's own ticket, project and timeline tables and writes the link as a normal ticket-timeline entry.
The one new table duplicates something False It's an inbox for incoming events — attempts, retry time, lease, result. A different job from recording a link.
It's over-built for where the project is True Signature checking, retry leases, deduplication, a 2,000-commit guard, and an abstraction for three code hosts we don't run yet.

What to do with it

  • Keep the work. The design is right and the link lands where the board can already see it. Deleting it would cost more than merging it.
  • The board question answers itself once this merges. Tickets stop being bare numbers — each one carries its own code.
  • Split the estimate next time. "Link a ticket to a PR" and "make it survive a hostile internet" are two decisions. Ask for the first; approve the second separately, on purpose.
  • Rename one of the two "bridges." The thing that runs commands on the Mac and the thing that connects Biplane to Forgejo share a name, and that alone cost us twenty minutes tonight.
